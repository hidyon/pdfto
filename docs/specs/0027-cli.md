## 1. 背景・目的

M6 で同梱クライアントを `pip install` 可能なパッケージ（`pdfto-client`・依存ゼロ）にした。
これを土台に、**コマンド一発で変換**できる CLI を提供して導入体験を上げる。CLI は依存ゼロを
保つため、ローカルで起動した（または任意の）PDFto **API サーバ**に対して動く薄いラッパとする
（重い docling を CLI に同梱しない）。

> サーバは `uvicorn app.main:app` か `docker run` でローカル起動できる。CLI は既定で
> `http://localhost:8000` を見る。サーバ非依存の「直接変換」は重い app/docling が必要なため
> 非スコープ（将来別途検討）。

## 2. スコープ

### やること
- `pdfto-client` パッケージに CLI エントリポイント `pdfto` を追加（`pdfto_client:main`）。
- サブコマンド：`health`（疎通確認）/ `convert <file>`（ワンショット変換）。
- グローバルオプション：`--server`（既定 `PDFTO_SERVER` 環境変数→`http://localhost:8000`）、
  `--api-key`（既定 `PDFTO_API_KEY`）、`--version`。
- `convert`：`-f/--format`（markdown/html/json/text）、`-o/--output`（既定 stdout）、
  `--ocr`、`--no-table`。
- README に CLI の使い方を追記。

### やらないこと（非スコープ）
- サーバ非依存のローカル直接変換（docling 同梱）。
- バッチ・対話質問フローの CLI 化（必要になれば追加）。
- 新しいクライアント API。

## 3. 要件

### 機能要件
- `pip install ./client/python` 後に `pdfto` コマンドが使える（`[project.scripts]`）。
- `pdfto --version` がバージョンを表示。
- `pdfto health` がサーバ状態を JSON 出力（疎通失敗時は stderr にエラー＋終了コード 1）。
- `pdfto convert file.pdf -f markdown` が変換結果を stdout（`-o` 指定時はファイル）へ出力。
  `--ocr`/`--no-table` がオプションに反映される。
- エラー（`PDFtoError`/IO）は stderr に出し、終了コード 1 を返す（正常は 0）。

### 非機能要件
- CLI は標準ライブラリのみ（argparse 等）。クライアントの依存ゼロを維持。
- 既存のクライアント API・サーバは不変。

## 4. 設計

### `client/python/pdfto_client.py`
- `main(argv=None) -> int` を追加（argparse）。`PDFtoClient` を `--server`/`--api-key` で構築し、
  `health()` または `convert_oneshot(file, output_format, do_ocr, do_table_structure)` を呼ぶ。
  出力は `-o` かなければ `sys.stdout.buffer`。例外は stderr＋return 1。
- 末尾に `if __name__ == "__main__": raise SystemExit(main())`。
- `argparse`/`os`/`sys` は `main` 内で import（ライブラリ利用時の footprint を増やさない）。

### `client/python/pyproject.toml`
- `[project.scripts]` に `pdfto = "pdfto_client:main"`。

### 影響範囲
- 変更: `client/python/pdfto_client.py`, `client/python/pyproject.toml`,
  `client/python/README.md`, `README.md`, `docs/roadmap.md`。
- 追加: CLI テスト（既存のサーバスレッド fixture を再利用）。
- サーバ本体・既定テストのアプリ挙動は不変。

## 6. テスト計画

- 既定 `python -m pytest`（`test_client.py` のサーバスレッド fixture を再利用）：
  - `main(["--server", url, "health"])` が 0 を返し JSON を stdout に出す（capsys）。
  - `main(["--server", url, "convert", pdf, "-f", "markdown"])` が変換結果を stdout に出す。
  - `-o` 指定でファイルに書ける。
  - 到達不能サーバで return 1。
  - `--version` が 0 で終了（SystemExit 0）。
- `pip install ./client/python` →`pdfto --version` のスモークは手動/任意。

## 7. リスク・代替案

- **サーバ必須**：CLI 単体では変換できず、サーバ起動が前提。README に明記。代替（docling
  同梱の直接変換）は重く依存ゼロを壊すため非採用。
- **stdout バイナリ出力**：出力は実質テキスト（md/html/json/txt）だが、安全のため
  `stdout.buffer` にバイト書き込みする。
