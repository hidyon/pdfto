# Spec: Web UI に API キー入力（認証付きで API を叩く）

- **ID:** 0019
- **状態:** done
- **マイルストーン:** M5 UI の追随
- **関連 issue:** M5-1（認証キー入力）
- **作成日 / 更新日:** 2026-06-21 / 2026-06-21

## 1. 背景・目的

`PDFTO_API_KEYS` を設定した認証有効デプロイでは、同梱 Web UI から `/api/v1/*` を
叩くと 401 になり、ブラウザだけでは使えない（spec 0006 / 0018 の既知課題）。

UI に **API キーの入力欄**を設け、保存したキーを全ての API 呼び出しに付与して、
認証有効環境でもブラウザから一通り操作できるようにする。

## 2. スコープ

### やること
- ヘッダに API キー入力欄を追加し、`localStorage` に保持（再訪時も復元）。
- 既存の全 API 呼び出し（アップロード/変換/ポーリング/履歴/再実行）に
  `X-API-Key` を付与。
- ダウンロード（結果・ZIP・履歴）を、ヘッダ認証が効くよう
  認証付き `fetch` → Blob 保存に変更（アンカー href 依存をやめる）。
- 401 時に「API キーが必要/不正」と分かるメッセージを出す。

### やらないこと（非スコープ）
- バックエンドの変更（クエリ文字列でのキー受理などはしない）。
- キーの検証エンドポイントやログイン UI、キー管理。
- キーの暗号化保管（`localStorage` 平文。利用者の自己責任である旨を明記）。

## 3. 要件

### 機能要件
- ヘッダの入力欄にキーを入れると `localStorage["pdfto_api_key"]` に保存され、リロード後も
  保持される。空にすると無認証として動く（既定デプロイの従来挙動）。
- アップロード・変換・ジョブ取得・履歴一覧・再実行の各 `fetch` がキー設定時に
  `X-API-Key` を送る。
- ダウンロード（結果のダウンロード/ZIP、履歴のダウンロード）が、キー設定時も成功する
  （Blob 取得 → 保存）。
- いずれかの呼び出しが 401 のとき、キーが必要/不正である旨を表示する。

### 非機能要件
- フロントエンドのみ（バニラ JS）。バックエンド・API は不変。
- 既定（無認証）デプロイでの挙動は不変。

## 4. 設計

### `app/static/index.html`
- ヘッダに `<input id="api-key" type="password" placeholder="API キー（任意）">` を追加。

### `app/static/app.js`
- `getApiKey()` / `setApiKey(v)`（`localStorage`）。
- `authHeaders(extra)`: キーがあれば `X-API-Key` を含めてヘッダを返す。
- 既存 `fetch` 呼び出しに `headers: authHeaders(...)` を付与。FormData は Content-Type を
  指定しない（ブラウザに委ねる）。JSON は `Content-Type: application/json` を併用。
- `downloadFile(url, filename)`: `fetch(url, {headers: authHeaders()})` → `blob()` →
  一時 `<a>` で保存。401 はエラー表示。
- 結果ダウンロード/ZIP/履歴ダウンロードを `downloadFile` 経由に変更。
- 初期化: ページ読込時に入力欄へ保存キーを復元し、`input` で保存。

### 影響範囲
- 変更: `app/static/index.html`, `app/static/app.js`, `app/static/style.css`（軽微）,
  `README.md`（UI 説明・任意）, `docs/roadmap.md`。
- Python・テストは不変。

## 5. 受け入れ条件（Definition of Done）

- [ ] キー入力欄があり、入力値が `localStorage` に保存・復元される。
- [ ] 認証有効デプロイで、キーを入れるとアップロード〜履歴〜再実行が動く。
- [ ] ダウンロード（結果/ZIP/履歴）がキー設定時も成功する。
- [ ] キー未設定の既定デプロイでの挙動は不変。
- [ ] 401 時に分かるメッセージが出る。

## 6. テスト計画

UI は自動テスト対象外。手動・スモークで確認：
- 静的ファイル配信され、`index.html` に `#api-key` が含まれる。
- 認証有効サーバ（`PDFTO_API_KEYS=...`）で、無キーは履歴が 401 メッセージ、キー投入後は
  一覧が取得できる（手動）。
- 既定サーバで従来どおり動く。

（バックエンドの認証自体は spec 0006 のテストで担保済み。）

## 7. リスク・代替案

- **localStorage 平文保管**：XSS 時にキーが漏れる。UI 同梱の利便機能であり、機密度の高い
  キーはサーバ間連携で扱う前提とし、README に注意を明記。
- **代替: クエリ文字列でキー受理**（アンカー DL が楽）。URL/ログ漏洩リスクがあるため
  不採用。ダウンロードは Blob 取得で対応する。

## 8. 未決事項

- キーの保存先は `localStorage`（タブ跨ぎ保持）。セッション限定にするなら
  `sessionStorage` だが、再訪時の利便を優先して `localStorage` とする。
