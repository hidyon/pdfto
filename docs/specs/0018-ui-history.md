# Spec: Web UI に履歴（ジョブ一覧・ダウンロード・再実行）

- **ID:** 0018
- **状態:** done
- **マイルストーン:** M5 UI の追随
- **関連 issue:** M5-2（ジョブ/ドキュメント一覧・再実行の UI）
- **作成日 / 更新日:** 2026-06-21 / 2026-06-21

## 1. 背景・目的

M4 で一覧（`GET /jobs`）・再実行（`POST /jobs/{id}/retry`）・配送履歴 API を追加したが、
Web UI は「1 件アップロード → 変換 → ダウンロード」の単発フローのままで、これらを
活かせていない。ブラウザだけで**過去のジョブを見て・落として・やり直せる**ようにする。

## 2. スコープ

### やること
- Web UI に「履歴」セクションを追加し、最近のジョブ一覧を表示する。
- 各ジョブに状態バッジ・出力ファイル名・形式・作成時刻を表示。
- `succeeded` はダウンロードリンク、各ジョブに「再実行」ボタンを表示。
- 更新ボタンと、変換完了時/ページ読込時の自動更新。
- 実行中（pending/running）が残る間は自動でポーリング更新。

### やらないこと（非スコープ）
- 認証キーの UI 入力（M5-1）。本 issue は無認証 or 既にキー不要の前提で動かす。
- バッチ投入 UI（M5-3）。
- ページャ UI（まずは直近 N 件のみ。`limit` 固定）。
- バックエンドの変更（既存 API のみ使用）。

## 3. 要件

### 機能要件
- ページ表示時に `GET /api/v1/jobs?limit=20` を取得し、新しい順で一覧表示する。
- 各行: 状態（pending/running/succeeded/failed のバッジ）、出力ファイル名（無ければ
  document_id）、`output_format`、作成時刻。
- `succeeded` の行は `download_url` へのダウンロードリンクを表示。
- 各行に「再実行」ボタン。押下で `POST /api/v1/jobs/{id}/retry` → 一覧を更新。
- 「更新」ボタンで再取得。変換ジョブ投入/完了時にも自動更新。
- pending/running が一覧にある間は数秒間隔で自動更新し、無くなれば停止。
- 取得が `401` の場合は「認証が必要です」と控えめに表示（M5-1 で対応予定）。

### 非機能要件
- 追加依存なし（バニラ HTML/CSS/JS）。既存のスタイル・配色に合わせる。
- バックエンド・API は不変。

## 4. 設計

### `app/static/index.html`
- `#step-result` の後に `<section id="history" class="card">` を追加：
  見出し「履歴」、`#refresh-history` ボタン、`#history-list` コンテナ、`#history-status`。

### `app/static/app.js`
- `loadHistory()`: `GET /api/v1/jobs?limit=20` → 行を描画。401 等はメッセージ表示。
- 行描画: 状態バッジ、ファイル名/ID、format、時刻、ダウンロード（succeeded）、再実行。
- `retryJob(id)`: `POST /jobs/{id}/retry` → 成功で `loadHistory()`。
- 自動更新: `loadHistory()` をページ末で初回実行・`showResult` 後・「更新」押下で実行。
  `pending`/`running` を含む場合のみ `setTimeout` で再ポーリング（多重起動を防ぐフラグ）。

### `app/static/style.css`
- 状態バッジ（`.badge.pending|.running|.succeeded|.failed`）と履歴行のスタイル。

### 影響範囲
- 変更: `app/static/index.html`, `app/static/app.js`, `app/static/style.css`,
  `README.md`（UI 説明・任意）, `docs/roadmap.md`。
- Python コード・テストは不変（フロントエンドのみ）。

## 5. 受け入れ条件（Definition of Done）

- [ ] トップページに「履歴」セクションが表示され、最近のジョブが新しい順に並ぶ。
- [ ] `succeeded` 行にダウンロードリンク、各行に再実行ボタンがある。
- [ ] 再実行ボタンで新ジョブが作られ、一覧が更新される。
- [ ] 実行中ジョブがある間は自動更新され、完了後に止まる。
- [ ] 既存の変換フロー（アップロード→質問→ダウンロード）は不変。
- [ ] サーバ起動でページ・静的アセットが配信され、`/api/v1/jobs` を参照する。

## 6. テスト計画

UI は自動テスト対象外（既存の `GET /jobs` / `retry` は spec 0016/0017 でテスト済み）。
手動・スモークで確認：
- 静的ファイルが配信され、`index.html` に `#history` 要素が含まれる。
- 変換を 1 件行い、履歴に `succeeded` 行とダウンロード/再実行が出る。
- 再実行で行が増える。

## 7. リスク・代替案

- **認証有効時に履歴が 401**：本 issue ではメッセージ表示に留め、M5-1 でキー入力を追加。
- **ポーリング多重起動**：実行中フラグで一本化し、停止条件（pending/running 不在）を明確化。
- **代替: ドキュメント一覧を主役にする**：操作（DL/再実行）はジョブ単位が自然なため、
  ジョブ一覧を主とする。

## 8. 未決事項

- 表示件数は直近 20 件固定（ページャは将来）。自動更新間隔は 2 秒で進める。
